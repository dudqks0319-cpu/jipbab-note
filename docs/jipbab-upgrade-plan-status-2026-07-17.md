# 집밥노트 업그레이드 계획 구현 상태

기준일: 2026-07-17
대상: `dudqks0319-cpu/jipbab-note`
작업 브랜치: `codex/jipbab-upgrade-plan`

## 판정 기준

- `완료`: 코드와 자동 검증이 현재 저장소에 존재한다.
- `로컬 완료`: 코드·migration·자동 검증은 존재하지만 운영 DB 또는 배포에는 적용하지 않았다.
- `부분`: 핵심 일부만 구현되어 계획서 완료 조건을 아직 충족하지 못한다.
- `외부 차단`: 사람 검수, 실제 조리, 실기기, 유료/운영 인프라 또는 계정 권한이 필요하다.
- `미구현`: 현재 저장소에서 구현 근거를 확인하지 못했다.

## 이번 작업에서 추가한 핵심 기능

### 구조화 알레르기 하드 필터 — 로컬 완료

- [식품안전나라 알레르기 표시 안내](https://www.foodsafetykorea.go.kr/portal/board/boardDetail.do?bbs_no=hpikbbs001&menu_grp=MENU_NEW05&menu_no=8083&ntctxt_no=1083285)에 맞춘 19개 표시 카테고리를 앱 상수와 설정 UI로 추가했다.
- 자유 입력 메모는 자동 필터에서 제외하고, 구조화 선택만 API 필터로 전달한다.
- `allergen_groups`, `ingredient_allergen_profiles`, `ingredient_allergen_links`를 추가했다.
- 모든 기존 재료 프로필은 `unreviewed`로 시작한다. 자동 추정값을 검수 완료로 승격하지 않는다.
- 사용자가 알레르기를 선택하면 미검수 재료가 하나라도 포함된 레시피를 추천/목록 후보에서 제외한다.
- `contains`, `may_contain`, `cross_contact` 관계를 모두 하드 제외 대상으로 처리한다.
- 새 DB 계약이 없거나 조회에 실패하면 알레르기 사용자의 요청은 정상 추천처럼 보이지 않고 503으로 닫힌다.

운영 적용 전 남은 일:

- migration 적용
- 카탈로그 173개 재료의 사람 알레르기 검수
- 가공식품 원재료/혼입 가능성 근거 입력
- 검수 완료 후 `approved`, reviewer, reviewed_at 기록

### 레시피 오류 신고 — 로컬 완료

- 레시피 상세에 로그인 사용자용 비공개 오류 신고 UI를 추가했다.
- 계량, 조리 설명, 시간·인분, 알레르기, 식품 안전, 사진, 출처·권리, 기타 유형만 허용한다.
- 본문은 3~500자로 제한하고 추가 필드는 거부한다.
- 서명된 영구 사용자 확인, 분산 요청 제한, 공개 v2 레시피 확인 후에만 접수한다.
- `recipe_issue_reports`는 공개 댓글과 분리된 비공개 운영 큐이며 사용자는 본인 신고만 읽고 쓸 수 있다.
- 접수 즉시 레시피를 자동 수정하거나 차단하지 않는다.

운영 적용 전 남은 일:

- migration 적용
- 운영자 triage/resolve UI
- 동일 신고 누적 임계값과 임시 경고 정책
- 변경 버전과 신고 해결 이력 연결

### 조리 완료 세션과 구조화 후기 — 로컬 완료

- 사용자가 조리 모드에서 시작한 시각, 완료 시각과 고유 세션 ID를 기기에 보존한다.
- 성공/아쉬움/실패, 체감 난이도, 맛, 다시 만들기, 대체 재료, 가족 반응, 짧은 메모를 구조화했다.
- 로그인 사용자가 `비공개 기록 저장`을 눌렀을 때만 서버에 적재한다.
- `cooking_sessions`는 사용자별 비공개 RLS 계약이며 같은 client session ID 재시도는 중복 생성하지 않는다.
- 이 데이터는 사용자 경험 원자료이며 편집·식품 안전·실제 조리 검수 승인으로 자동 승격하지 않는다.

운영 적용 전 남은 일:

- migration 적용
- 운영 분석용 집계 뷰와 최소 표본 기준
- 포토 후기의 저장소, 권리 동의, 이미지 검수 정책

### 실제 주간 식단 — 로컬 완료

- `meal_plans`, `meal_plan_items`와 아침·점심·저녁 21개 슬롯을 추가했다.
- 추천 메뉴 7개를 보기만 하던 화면을 사용자가 실제로 선택·교체·비우는 영속 식단으로 변경했다.
- 남은 음식, 외식, 배달, 기타 메뉴를 레시피와 구분해 저장한다.
- 비로그인 사용자는 기기에 저장하고, 로그인 사용자는 명시적인 API를 통해 개인 계정과 동기화한다.
- 주간 식단의 공개 레시피만 서버에 저장하며, 항목 교체는 DB 함수 한 트랜잭션에서 처리한다.
- 선택한 레시피의 부족 재료를 기존 장보기 중복 병합 흐름으로 한 번에 보낸다.
- 기기 식단과 계정 식단이 다르면 자동 덮어쓰지 않고 두 선택지를 보여 준다.
- 레시피 제목은 클라이언트 표시값이 아니라 서버의 공개 레시피 제목으로 고정한다.

운영 적용 전 남은 일:

- migration 적용
- 가족 식단 scope와 구성원별 식사 여부
- 남은 음식의 이전 식사 참조
- 수치 계량의 단위별 주간 합산

### 계정 삭제 로컬 정리 — 완료

- 원격 계정 삭제 후 기기의 냉장고, 장보기, 즐겨찾기, 가족 보드, 식단, 조리 진행, 커뮤니티 초안, 외부 레시피 북마크를 선별 삭제한다.
- 공개 레시피 캐시, 분석 동의, 기기 식별자는 계정 데이터와 분리해 유지한다.
- 로컬 삭제가 실패하면 계정 삭제 성공과 기기 정리 실패를 분리해 사용자에게 안내한다.
