# OPS-005 조리 모드 점진 활성화

Updated: 2026-07-15 KST

## 설정 계약

- 서버 전용 `COOK_MODE_ROLLOUT_PERCENT`만 사용한다. 브라우저 번들, 쿼리 문자열, 쿠키로 값을 전달하거나 우회하지 않는다.
- 허용값은 공백 없는 정수 `0`부터 `100`까지다.
- 값이 없으면 기존 동작을 보존하기 위해 `100`으로 판단한다.
- 값이 명시됐지만 비어 있거나 범위를 벗어나거나 정수가 아니면 `0`으로 판단해 조리 모드를 닫는다.
- 레시피 ID만 해시해 0~99의 고정 버킷을 만든다. 사용자, 기기, 세션, 이메일, IP를 수집하거나 저장하지 않는다.
- 대상 레시피는 `bucket < percentage`일 때만 한 단계 조리 모드를 표시한다. 같은 레시피는 배포 사이에도 같은 버킷을 유지한다.

조리 모드가 닫힌 레시피에도 검수된 인분, 재료, 장보기 보조와 일반 조리순서는 그대로 표시한다. 상단의 `조리 시작` 동작은 `순서 보기`로 바뀌고, 화면 하단에는 점진 공개 중이라는 안내만 표시한다.

## 점진 활성화 절차

1. Preview에 `COOK_MODE_ROLLOUT_PERCENT=0`을 적용한 새 배포를 만든다.
2. 공개 승인 레시피 상세에서 `순서 보기`가 일반 조리순서로 이동하고 조리 모드가 렌더링되지 않는지 확인한다.
3. 같은 commit으로 `10`을 적용해 버킷이 낮은 레시피만 조리 모드를 표시하는지 확인한다.
4. 오류율, 조리 시작·완료·중단 흐름, 지원 문의를 확인한 뒤 `25`, `50`, `100` 순서로 올린다.
5. 각 단계는 새 배포 ID, commit SHA, 비율, 확인 시각과 운영자 승인을 현재 출시 원장에 기록한다.

비율 변경만으로 실제 사용자 조리 검수, 기기 QA, Production 승인 증거를 대체하지 않는다. 공개 승인 레시피가 없는 환경에서는 버킷 로직과 비활성 fallback만 검증하고 실제 시작·완료율을 주장하지 않는다.

## 즉시 차단과 복구

1. 장애 시 해당 Vercel 환경의 `COOK_MODE_ROLLOUT_PERCENT`를 `0`으로 설정한다.
2. 마지막으로 확인된 commit을 새로 배포하고 deployment SHA가 그 commit과 같은지 확인한다.
3. 레시피 상세에서 `순서 보기`, 일반 조리순서, 재료와 장보기가 유지되고 조리 모드는 보이지 않는지 확인한다.
4. 서버 오류와 최근 배포 로그를 확인한 뒤 결과를 출시 원장에 기록한다.
5. 원인이 수정되고 동일한 검증을 다시 통과하기 전에는 비율을 올리지 않는다.

이 절차는 비파괴 코드 차단이다. 기존 로컬 조리 진행 데이터, 레시피 데이터와 DB schema를 삭제하지 않는다. Vercel Production 값 변경과 alias 전환은 운영자 승인 이후에만 수행한다.

## 현재 적용 상태

- 코드와 테스트: 구현 완료
- `.env.example`: 기본값 `100` 기록
- Vercel Preview/Production 비율 변경: 미실행
- Production 활성화 승인: 미실행
- DB migration과 새 의존성: 없음

## 잔여 위험

- Owner `Product+QA`, due `before_rollout_above_10_percent`: 공개 승인 레시피와 실제 초보 사용자로 조리 시작·완료·중단을 확인한다.
- Owner `FullStackDev+SRE`, due `before_production_rollout`: Production env 변경, 새 deployment SHA, 장애 시 0% 차단과 post-deploy 로그를 확인한다.
- Owner `FullStackDev`, due `before_remote_config_requirement`: Vercel 재배포보다 빠른 원격 차단이 제품 요구가 되면 인증·감사로그를 포함한 별도 server-side control plane을 설계한다.
